# 技术主题页面

先阅读项目根目录的 `AGENTS.md`，并检查相关主题的数据和共享布局。页面结构、样式、图表和解说以项目规范为准；现有实现用于了解数据格式，若与规范不一致，以规范为准。

正式页面由 `localized.njk` 和 `_includes/` 中的共享布局生成。`templates/` 仅供开发参考，不参与正式构建或站点导航。优先沿用共享布局和资源，不要为主题创建独立的内嵌样式与脚本页面。

新增主题时：

1. 在 `topics.js` 登记主题 key、页面地址和分类。
2. 为站点支持的每种语言，在 `locales/<语言>/topics.js`、`content.json` 和 `steps/` 中提供导航、页面内容和步骤数据，并在该语言的 `index.js` 中关联步骤文件。参照现有主题确定数据格式；导航由登记信息和语言数据生成。
3. 确保各语言的标题、导语、整体图、步骤、补充说明和页脚完整，流程与关键边界一致。修改已有主题时，同步更新受影响的语言版本。

梳理参与方、动作顺序和数据或状态变化，用图文解释因果关系。区分协议要求、常见实现和产品策略；对不确定的技术事实查证可靠资料，不为凑版式编造步骤或结论。

完成后运行 `npm run build`，并按 `AGENTS.md` 验证各语言导航和切换、步骤交互、图文对应、Mermaid 渲染、响应式布局及键盘操作。说明无法完成的验证。

Session Cookie 登录

浏览器登录的常见做法。服务器保存「这次登录是谁」，响应里用 Set-Cookie 交给浏览器一个不透明的 session id。之后同站请求由浏览器自动带上 Cookie，服务器用这个 id 查回用户。页面脚本不必自己把令牌抄进 Authorization。

现在两边各有什么

session 和 cookie 各管一件事

服务器上的 session浏览器里的 cookie
存什么 用户 id、登录时间、过期时间。真正的登录状态在这里。 只存一个随机的 sid。用户资料不放进 cookie。
怎么出现 账号密码校验通过后写入存储，键就是这个 sid。 响应头 Set-Cookie: sid=...; HttpOnly; Secure; Path=/; SameSite=Lax。
下次请求 用请求头里的 sid 查表。查不到或已过期，就当作未登录。 域名、路径、过期时间都匹配时，浏览器自动加上 Cookie: sid=...。
登出 删掉这条记录。即使浏览器还带着旧 sid，查表也失败。 再回一条 Set-Cookie: sid=; Max-Age=0，让浏览器丢掉它。

HttpOnly 让页面脚本读不到这份 cookie。Secure 只在 HTTPS 下发送。SameSite=Lax 让别的网站发起的请求默认不带上它，用来减轻跨站请求伪造。真正让登录失效的是服务器删掉 session，cookie 只是那把查表用的编号。

这是浏览器 Session Cookie 的一般过程。令牌登录见 Access token 与 Secret token。

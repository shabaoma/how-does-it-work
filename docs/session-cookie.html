SESSION FLOW

整体流程：浏览器如何保持登录

flowchart LR B[浏览器] -->|提交登录凭证| S[服务器] S -->|保存登录会话| D[(Session 存储)] S -->|Set-Cookie 返回会话编号| B B -->|后续请求携带 Cookie| S S -->|按编号查询会话| D S -->|返回业务结果| B

Cookie 携带会话编号；服务器通过会话存储确认登录状态。

session 和 cookie 各管一件事

服务器上的 session浏览器里的 cookie
存什么 用户 id、登录时间、过期时间。真正的登录状态在这里。 只存一个随机的 sid。用户资料不放进 cookie。
怎么出现 账号密码校验通过后写入存储，键就是这个 sid。 响应头 Set-Cookie: sid=...; HttpOnly; Secure; Path=/; SameSite=Lax。
下次请求 用请求头里的 sid 查表。查不到或已过期，就当作未登录。 域名、路径、过期时间都匹配时，浏览器自动加上 Cookie: sid=...。
登出 删掉这条记录。即使浏览器还带着旧 sid，查表也失败。 再回一条 Set-Cookie: sid=; Max-Age=0，让浏览器丢掉它。

HttpOnly 让页面脚本读不到这份 cookie。Secure 只在 HTTPS 下发送。SameSite=Lax 限制部分跨站请求携带 cookie，以减轻跨站请求伪造；部分安全的顶层导航仍可能携带。真正让登录失效的是服务器删掉 session，cookie 只是那把查表用的编号。

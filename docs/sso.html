整体流程：应用与外部身份提供方协作

浏览器负责跳转，应用与身份提供方分别维护会话。虚线表示双方配置并支持时，身份提供方可通知应用退出。

两种会话与退出范围

会话作用退出后的影响
应用会话应用识别后续请求中的用户。清除本地会话后，该应用不再认可它；身份提供方会话可能仍有效。
身份提供方会话身份提供方记住已认证用户，让其他应用可以复用认证状态。结束后通常需要重新认证；其他应用已有的本地会话不一定同时失效。

只退出应用后再次点击登录，若身份提供方会话仍有效，用户可能无需再次输入凭据。

接入与退出的关键边界

  • 事先建立信任：在身份提供方注册客户端和精确的回调地址，使用可信配置获取端点和签名密钥；全程使用 HTTPS。
  • 保护登录回调：校验 state 以关联请求和回调；使用 PKCE 绑定授权码，并在发送 nonce 时校验它。校验 ID Token 的签名、签发方、受众和有效期等，失败则不建立会话。
  • 账号映射：使用可信签发方 iss 与主体 sub 标识外部身份；是否自动创建或关联本地账号由应用策略决定，不应仅凭未经验证的邮箱绑定账号。
  • 退出传播：应用发起的身份提供方退出与向其他应用传播退出是独立能力。前端或后端通知需要对应应用和提供方支持与配置，通知也可能失败，不能保证所有会话立即结束。
  • 令牌生命周期：清除会话或退出身份提供方不一定撤销已签发的访问令牌；需要时按提供方能力撤销令牌，并控制其有效期。

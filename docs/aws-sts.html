OVERVIEW

整体流程：跨账户访问

flowchart LR C[调用方] -->|AssumeRole 请求| S[STS] S -->|检查角色信任及调用权限| I[IAM 策略] S -->|返回临时凭证| C C -->|签名请求与会话令牌| R[AWS 资源服务] R -->|授权后返回结果| C

此图以跨账户角色为例；身份联合和 AWS 服务提供凭证的路径有所不同。

临时凭证包含什么

字段用途
AccessKeyId标识用于签名的临时访问密钥。
SecretAccessKey用于计算请求签名，需要保密，不直接作为请求参数发送。
SessionToken随临时凭证签名的请求一起提供；它不是单独使用的刷新令牌。
Expiration凭证失效时间；到期后需要取得一组新的凭证。

其他入口与权限边界

  • 身份联合：AssumeRoleWithWebIdentity 使用受信任身份提供方的令牌，AssumeRoleWithSAML 使用 SAML 断言；它们不是本页的跨账户 AssumeRole 请求。
  • 会话权限：角色权限策略提供权限；可选的会话策略用于进一步限制，不能扩大角色基于身份的权限。实际授权还可能受资源策略、权限边界、组织策略和显式拒绝影响。
  • 有效期：AssumeRole 默认一小时，可请求 15 分钟至角色配置的最大会话时长（最大可配置为 12 小时）；角色链式切换最多一小时。
  • 自动更新：部分 AWS SDK 凭证提供程序和 AWS 计算服务会在到期前获取新凭证；自行管理凭证时需处理更新。

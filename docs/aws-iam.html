常见策略各管什么

策略或限制作用
基于身份的策略附加到用户、组或角色，授予或拒绝操作。
基于资源的策略附加到支持该策略的资源，指定主体及其允许或拒绝的操作，例如 S3 存储桶策略。
权限边界与会话策略限制身份或角色会话可获得的基于身份的权限，本身不授予权限；资源策略直接授权给某些主体时有特殊规则。
组织控制策略服务控制策略（SCP）和资源控制策略（RCP）分别限制适用主体或资源的最大权限，本身不授予权限，适用范围和例外不同。

理解授权的边界

  • 同账户：身份策略或资源策略可以提供允许，但其他适用限制仍可能阻止请求。资源策略直接授权给 IAM 用户或角色会话时，权限边界和会话策略中的隐式拒绝有特殊规则；显式拒绝仍生效。
  • 跨账户：通常需要调用方账户和资源账户两侧都允许；具体评估取决于访问方式及服务。代入另一账户的角色后，使用的是该角色会话。
  • 角色信任：信任策略控制谁可以代入角色；取得角色会话后，访问资源仍须单独授权。
  • 服务特定控制：S3 还可能受阻止公开访问等设置影响；IAM 评估通过也不代表操作一定成功，例如对象不存在或加密密钥权限不足。

实现时要守住的边界

  • 生成和保存：用密码学安全随机数生成验证码；服务端保存邮箱、用途、到期时间、尝试次数和验证码的校验值。短数字码很容易被离线枚举，可使用服务端密钥计算 HMAC，并将密钥与存储分离；不要记录明文验证码。
  • 短期、一次有效：例如 6 位数字、5～10 分钟有效；成功时原子地校验并消费，过期或使用后不能再用。重新发送时明确使旧码失效或限制同时有效的码。
  • 限制滥用：按邮箱、IP 等维度限制发送和验证次数，设置重发冷却；对不存在和存在的账号尽量给出一致的提示，减少账号枚举。
  • 建立会话：全程使用 HTTPS；成功后创建新的随机 Session ID，Cookie 设置 Secure、HttpOnly 和合适的 SameSite，并根据应用需要防范 CSRF。
  • 账号策略：验证成功后查找已有账号；是否允许新邮箱自动注册由产品策略决定。验证码不应让用户转发给别人。

安全性依赖邮箱和邮件链路；这不等于多因素认证，也不能防钓鱼。高风险操作可增加 Passkey 等抗钓鱼认证。NIST 的数字身份指南不允许将邮箱作为带外认证通道。

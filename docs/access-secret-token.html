TOKEN FLOW

整体流程：两种令牌如何使用

flowchart LR C[客户端] -->|登录凭证| A[认证服务器] A -->|签发访问令牌和刷新令牌| C C -->|访问令牌| B[业务服务器] B -->|业务结果| C C -.->|访问令牌过期时提交刷新令牌| A

图中 secret token 指刷新令牌；是否签发或轮换刷新令牌取决于系统设计。

两张令牌各做什么

access tokensecret token
发给谁 业务服务器。通常放在 Authorization: Bearer。 认证服务器的换发接口。业务请求里不出现它。
有效期 短。过期后业务服务器直接拒绝。 长。用来在 access token 过期后续上一张新的。
服务器怎么认 核对签名、过期时间和权限范围，通过就执行这次调用。 在认证服务器上查这张是否仍有效。有效才签发新的 access token。
登出 已发出的那张会留到自己的过期时间。 注销这张之后，就不能再换发。这是让登录停下来的那一步。

应用向认证服务器证明「我是哪个应用」时，用的是另一份应用密钥，一般叫 client secret。它在用户登录之前就配置在服务端或机密客户端里，和登录后发给这个用户的 secret token 是两份东西。
